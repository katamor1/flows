# C90実装とレビューの指針

## 仕様を実装の契約として読む

関数・型・引数・戻り値、初期状態、所有権、成功時とエラー時の更新、処理順序を抽出する。入力を無視する条件やエラー優先順位は原仕様に従う。仕様IDや手順IDの名前・個数、しきい値、戻り値、状態の有無をサンプルに合わせない。準備ツールが受理する共通インターフェイス以外の仕様構造は案件に応じて読解する。

コードの都合で仕様や独立試験を修正しない。試験の期待値を被試験関数から作らない。不足・矛盾を見つけたら該当箇所を記録し、仕様または試験の保守改訂と実装修正を分ける。WordとJSONが食い違う場合は、JSON正本との差異を報告する。

## C90と既存DLL

- 宣言はブロックの先頭に置く。C99以降の混在宣言、for内宣言、`//`、`bool`、`stdint.h`、可変長配列等を持ち込まない。
- APIに定められた型・呼出し規約を使う。`int` や `long` の幅を推測せず、オーバーフロー、符号変換、数値精度を対象仕様と正式環境で確認する。
- 汎用ホスト検証のC/HはUTF-8を使う。ASCIIもその範囲に含む。コメントの文字コードとC90の言語規格は別の条件であり、ホストClangの結果からプロジェクト固有の文字コードや正式コンパイラ対応を保証しない。
- 標準パスは `include/<routine_name>.h` と `src/<routine_name>.c`。生成ヘッダは固定テンプレートに仕様の型・宣言を一度展開した契約であり、本体に合わせて編集しない。SDKの依存ヘッダは提供プロファイルからコピーする。
- 公開API、DllMain、DLLエクスポート、SDKのスタブは対象仕様と正式契約が要求する場合に限る。DLL内部の関数と公開インターフェイスを区別する。

## RTOS・状態・外部依存

ファイル、時刻、CPUロック、レジスタI/O等は、提供APIの契約で許される文脈から呼ぶ。Win32やCランタイムの直接操作へ勝手に置き換えない。API名に加えて実行文脈、ブロックの有無、戻り値、失敗時処理、ロックの解除条件を確認する。正式RTOS SDK・DLL ABI・呼出し規約が未提示なら、その接続は未決として残す。

状態・出力領域の寿命、非重複、再入可能性、他タスクからのアクセスを確認する。`volatile` だけで同期が成立すると扱わない。ロック・待機・動的確保・再帰・文字列整形は仕様と時間予算に従い、ループは上限を説明する。状態や外部APIを使うこと自体を禁止せず、対象仕様の制約を確認する。

プロファイルのサポートソースはホスト試験の接続手段である。合成APIのfixtureやモックを実RTOSの正式APIとして扱わず、モックでの成功から実環境の動作を保証しない。外部シンボルの許可は呼出しの機能・副作用・ABIの正しさを承認するものではない。

## 対応表と検証

`traceability.md` は仕様ID/処理 → 実装箇所 → 確認方法を示す。IDがない仕様は原文の所在を参照する。コードの行番号だけに依存せず、関数名とコードハッシュを追跡できるようにする。未実装・呼出し側責務・未決事項も残す。

ビルドと動的試験は別々の結果として記録する。C90モード・警告・最適化条件、試験対象、ツール版・入力版を追跡する。試験未提供なら `compiled_only` と報告し、機能正当性の合格へ読み替えない。試験があっても、その仕様と提供試験が確認した範囲を示す。

処理量が有界なことから実機WCETを保証しない。ハッシュと自己申告の生成記録は誤変更の検出・来歴管理であり、署名・権限制御・第三者認証ではない。
