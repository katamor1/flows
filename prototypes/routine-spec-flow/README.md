# 1ルーチンのプログラム仕様書を作るフローの試作

アラーム要求例から、DLL内部の連続ON判定ルーチン `AlarmQualification_Update` 1本のプログラム仕様書を作成した。仕様の正本はJSON、確認用の文書はWord、書式は差込タグ付きWordテンプレートに分けている。

今回のAIによる要求分析・正本作成は本チャットで実施した。正本検証とWord展開はローカルの決まった処理で行い、展開時にAIを呼ばない。モデルAPIを定常呼出しするエージェント基盤や、Cプログラムの実装は今回の試作範囲に含まない。

## 試作の範囲と仮定

対象ルーチンは入力サンプルの連続ON判定と新規成立通知を担当する。PLC信号取得、表示灯への出力、画面公開、ログ予約は呼出し側へ割り当て、要求との対応を仕様書に示した。

各周期に1回呼び出し、10回目の有効ONで成立し、ON継続中の新規成立は1回だけ返す。OFFまたは入力無効ではカウントを0へ戻す。これらは試作用の前提であり、利用者が承認した実システムの動作ではない。仕様書の未決事項に、前提確認・時間予算・既存規約との整合・呼出し側の設計を残している。

## ファイルの役割

| パス | 役割 | 通常の編集 |
|---|---|---|
| `source/alarm_qualification.json` | 仕様内容の管理正本 | 仕様変更はここで行う |
| `schema/routine-spec.schema.json` | 正本の項目・型・必須条件 | データ契約を改訂するときに変更 |
| `templates/routine-spec-v01.docx` | 文書の見出し・表・差込タグ・書式 | Wordで書式を試すときに変更 |
| `tools/flow.py` | 検証・差込み・表の繰返し・manifest生成 | 展開機能を変更するときに変更 |
| `build.ps1` | PowerShellから再生成する入口 | 通常は編集不要 |
| `output/PS-RTN-ALM-001.docx` | 生成した確認用プログラム仕様書 | 変更は正本またはテンプレートへ戻す |
| `output/manifest.json` | 入力・テンプレート・出力等のSHA-256 | 自動生成 |
| `output/verification.json` | フロー自動検査の結果 | 自動生成 |
| `tools/verify_flow.py` | 再生成・負例・内容保持の検査 | 検査内容の変更時に編集 |
| `qa/` | 検証用の複製・PDF・ページ画像 | 納品本文ではなく内部確認用 |

JSON SchemaはDraft 2020-12の形式で保存する。初回だけサンプルから形を作り、その後は独立した契約ファイルとして固定する。通常のビルドではスキーマを再生成しない。

## 再生成

必要なライブラリは `python-docx` と `lxml`。今回の実行ではCodexのバンドルPythonとライブラリを使用した。追加インストールやOfficeCLIの導入は行っていない。Word文書の生成そのものにMicrosoft Wordは不要である。

確認環境はPython 3.12.14、python-docx 1.2.0、lxml 6.1.1。依存ライブラリの固定値は`requirements.txt`にも保存した。

PowerShellで、ライブラリを使用できるPython実行ファイルを明示して実行する。

```powershell
.\build.ps1 -PythonExe 'C:\path\to\python.exe' -Verify
```

今回使用した環境では次の形で実行できる。バンドル更新後はアプリの依存関係取得でPythonのパスを再確認する。

```powershell
.\build.ps1 -PythonExe 'C:\Program Files\WindowsApps\OpenAI.CodexPrimaryRuntime.v26-1111-570-0_26.1111.570.0_x64__3k8sg7r9htsxt\dependencies\python\python.exe' -Verify
```

仕様だけを変える場合はJSONを編集して再実行する。テンプレートだけを変える場合はWordでテンプレートを編集・保存し、同じコマンドを実行する。`flow.py template` はテンプレートをコードから作り直す初期化用コマンドなので、Wordで編集した書式を使う通常運用では実行しない。`flow.py init-schema` も初期化用であり、負例を通すために再生成しない。

## テンプレートと正本の対応

本文・ヘッダ・フッタの `{{document.id}}` 等はJSONのパスを表す。表の見出し行は残し、試作行を正本の配列件数分複製する。繰返し表の指定はOOXMLの `tblCaption` に `repeat:配列パス` として保持する。試作行の `{{id}}`、`{{text}}` 等はその配列レコード内の項目を表す。

| 繰返し表 | JSONの配列または表示用データ |
|---|---|
| 試作用の前提 | `trial_assumptions` |
| 引数 | `interface.parameters` から型と契約を連結した表示用データ |
| 状態 | `behavior.state_fields` から範囲と意味を連結した表示用データ |
| 結果項目 | `behavior.result_fields` |
| 処理手順 | `behavior.steps` |
| 条件表 | `behavior.decision_rows` |
| 戻り値 | `interface.return_codes` |
| 制約 | `constraints` |
| 入出力例 | `verification_examples` |
| 要求対応 | `traceability` |
| 未決事項 | `open_issues` |

Wordでテンプレートを編集するときは、差込タグ、表の見出し行＋試作行、表の繰返し指定を維持する。タグが1つの文字書式範囲に収まる場合は、その書式を使って置換する。タグが複数範囲へ分断された場合は段落の先頭書式へまとめるが、ページ番号等のWordフィールドが混在する段落では処理を停止する。段落内に複雑な文字装飾を混在させる用途、入れ子の繰返し、画像・図の動的生成は未対応である。

正本のSHA-256の先頭12桁をフッタへ記載し、全ハッシュをmanifestへ保存する。同じPython・ライブラリ・スキーマ・テンプレート・正本での再生成は、ZIP内タイムスタンプを固定してバイト単位で一致する。異なるツール版をまたぐバイナリ一致や、別のWord環境での改ページ一致は保証しない。

## 検証方法と確認した範囲

自動検査では次を確認する。

1. 正常な正本を受け付ける。
2. 必須項目の欠落を拒否する。
3. 未定義の項目を拒否する。
4. 型が違う値を拒否する。
5. `approved`への変更を拒否する。この試作に承認機能はない。
6. IDの重複を拒否する。
7. 同一入力からの2回の生成がバイト単位で一致し、配布する生成物とも一致する。
8. 主要な仕様内容と繰返し行が欠落せず、未置換タグが残らない。
9. 正本の版を変更すると文書にも反映される。
10. テンプレートの差込タグと、タイトル下に不要な罫線がないことを確認する。
11. 差込み処理がWordのページ番号フィールドを壊していないことを確認する。

組み込みの検証器は、このスキーマで使用する明示的なキーワードだけを実装している。完全な汎用JSON Schema検証器ではない。未対応の検証キーワードを追加した場合は停止する。正式採用時はフル機能の検証器へ置き換えるか、この限定範囲を保守する。

仕様内容は別のレビュー担当にも読ませ、並行呼出し時の出力領域所有条件を補正した。仕様書の確認例はCプログラムの試験実績ではない。制御ルーチンのコンパイル・実行、RTOS接続、性能計測は未実施である。

文書の表示確認にはMicrosoft WordでのPDF出力と、PDF.jsによるページ画像化を使用した。標準の `render_docx.py` は、このWindows環境にLibreOfficeが配置されていないため実行できなかった。Wordでの確認経路は今回の代替であり、無人CI用の文書レンダラの確立は次の検証事項となる。

Wordで確認するときは生成物のコピーを開き、名前を付けて保存でPDFを選び、保存後のページ全体を確認する。ページ番号はWordが計算する。配布するDOCXは生成処理の出力を保持し、Wordの自動保存で書き換わったコピーとは分ける。確認用のPDF・ページ画像は一式ZIPには含めない。

## 今回の試作から次に判断すること

まず生成したWordで、章構成・表の粒度・引数や状態の表現・ルーチン1本あたりの文書量を確認する。次にJSONの記述負担と差分の読みやすさを確認する。書式が固まった段階で、実RTOS APIを利用するルーチンを1本追加し、基盤契約や外部依存を同じ形式で表現できるかを検証する。

今回の展開方式をそのまま本番標準と決定する必要はない。入れ子表・図・高度なWord編集が必要になれば、同じ正本からdocxtplやOfficeCLI等の変換器を比較できる。
