# C90ソース生成PoCの結果

既存のJSON正本 PS-RTN-ALM-001 revision 0.1から、DLL内部関数 `AlarmQualification_Update` のC90ヘッダと実装を作成した。成果物と再検証方法は [PoC README](../../prototypes/routine-code-poc/README.md) にまとめた。前段Word展開と同じ正本をハッシュで固定し、原仕様のP-01〜P-05をコードへ対応づけた。

Clang 22.1.3 / Windows x64 / 厳格C90診断で、O0とO2の両方が各1,948,941チェックに合格した。長さ11の3値全177,147系列、全有効状態、異常優先順位・エラー時無更新を含む。独立試験は本体実装前に仕様だけから作り、未実装スタブで失敗することを確認した。独立AIレビューでも本体の仕様不一致は見つからなかった。

制御ロジックを生成するのはAIであり、固定スクリプトは入力・生成記録の照合、コンパイル、試験、オブジェクト検査を担当する。固定スクリプトが特定の正解コードを出力する仕組みにはしていない。試験と指示も同じ資産を使い回す。

今回はCodexが生成した。導入済みBob Shellの非対話実行に必要なAPIキーが現在環境にないため、Bobによる生成実行は未確認として区別し、Bob IDE向けの固定指示書を付けた。Bob IDEでの実行、正式Cコンパイラ、対象RTOSでのABI/実行時間、未承認の試作仮定はチーム受入事項として残る。新しいAI生成でも入力・ヘッダ・試験を維持し、別案件コピーで生成記録の主体とコードハッシュを更新する。

元の要求にあるPLC入力、表示灯、画面公開、ログ処理は、この仕様書で呼出し側へ割り当てているため今回の関数に含めない。実行基盤の提供関数を推測して生成しない。納品用単体テスト仕様書の作成は次工程である。

配布物は [ソース生成PoC ZIP](../../artifacts/routine-code-poc/RTN-ALM-001-code-poc-0.1.0.zip)。全内容の読み戻しとハッシュ照合に加え、展開先で同じO0/O2試験を再実行して合格した。正本・本体・試験・ヘッダをそれぞれ変更すると検証が停止し、既存runも上書きしないことを [配布検査記録](../../artifacts/routine-code-poc/distribution-check.json) に残した。
