## 工程を接続した確認

状態と閾値のないRangeClampのフル仕様JSONを共通入力にした。コード担当は過去の本体・模範実装・独立試験ソースを読まずに本体を作成し、固定された独立試験15例がO0/O2の両方で成功した。その実際のコードjobからUT入力を取り込み、3ケース・1パラメータ族・1静的確認項目のUT JSONとWordを作成した。

プログラム仕様Wordの正本、コード生成入力、生成記録、UTへ取り込んだ正本/C/Hの全ハッシュが一致した。UT仕様で新たに作成した項目の実施記録は全て`not_executed`で、先行するコードのホスト試験合格を転記していない。

## 配置とレビュー

このプロジェクトの3スキルは統合ZIPの64ファイルとバイト単位で一致し、配置後doctorは全て成功した。[配置記録](install-output.json)に旧版の退避先を保存した。無関係な`.bob`設定やGitのglobal設定を変更していない。導入ツールは検証したZIPをメモリに固定し、同じ内容だけを配置する。

独立レビューで見つかった「任意JSON内のidを仕様の宣言IDと誤認する問題」と「ZIP検証後の再読込で内容が変わり得る問題」は修正し、各回帰を確認した。Windowsで一時的にディレクトリのrenameが拒否された事象は、変更なしの同一操作で成功することを確認した。導入ツールは宛先不存在を毎回確認し、短時間のPermissionErrorだけを有限回再試行する。恒久的な失敗は停止し、更新済み資材を戻す。

[Gitの改行変換検査](git-roundtrip-combined/verification.json)では、`core.autocrlf=true`を指定した隔離したGit作業領域で、配布資材と意図的なCRLF入力の67ファイルを往復し、全バイトの保存を確認した。ルートリポジトリのメタデータには書き込んでいない。
