# Bob IDEでのソースコード生成指示（このPoC用・再利用）

このフォルダをBob IDEのワークスペースとして開き、このファイルを添付して実行する。
以下の相対パスはこのPoCフォルダを基準とする。自動スクリプトやテンプレートは再生成しない。

1. `job.json` と `input/spec.json` を読む。入力SHA-256を照合する。正本を変更しない。
2. `include/AlarmQualification.h` は正本から抜き出した固定インターフェイスである。変更しない。
3. 正本に従って `src/AlarmQualification.c` だけをC90で実装する。既存実装を再生成する場合は別コピーで実行し、差分をレビューする。ASCII、C90コメント、関数1個、共有状態なし。しきい値は10、判定順序とエラー無更新を厳守する。RTOS/Win32/標準ライブラリ関数を呼ばない。DLLエクスポート、DllMain、ハードウェア接続、独自APIや未指定動作は追加しない。
4. `tests/` と `tools/codeflow.py`、`qa/unimplemented.c` は固定資産として変更しない。テストを読むことで実装を合わせるのでなく、正本の手順P-01～P-05を根拠とする。
5. 別コピーの `generation-record.json` に、実際の生成AI、Bob IDE版、Bob実行の有無、生成したソースのSHA-256を新たに記載する。固定の正本・ヘッダ・試験のハッシュは維持する。元のコピーや過去の検証記録にBob実行済みと上書きしない。固定検証はこの記録と対象ファイルのハッシュ一致も検査する。
6. READMEの固定検証コマンドを新しい出力ディレクトリで実行し、コンパイルエラーと仕様不一致を実装側で直す。修正時は新しいコードのハッシュを生成記録へ反映し、新しいrun IDで検証する。正式プロジェクトのコンパイラ、RTOS結合、WCETの未検証を明記する。

判断不能な場合は正本の `open_issues` に対応する事項を報告し、仕様を黙って補完しない。これは要件承認前の試作であり、製品DLLの完成指示ではない。
