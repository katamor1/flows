# C90実装とレビューの指針

## 仕様を実装の契約として読む

関数/型/引数/戻り値、初期状態、所有権、成功時とエラー時の更新、処理順序を抽出する。入力の無効とOFFを区別し、無効時に無視する値を勝手に検査しない。「10サンプル」と「10周期経過」のような時間解釈は原仕様に従う。

コードの都合で仕様や独立試験を修正しない。試験の期待値を被試験関数から作らない。試験の不足・仕様との矛盾を見つけた場合は具体的に記録し、仕様または試験の保守改訂と実装修正を分ける。

## C90と既存DLL

- 宣言はブロックの先頭に置く。C99以降の混在宣言、for内宣言、`//`、`bool`、`stdint.h`、可変長配列等を持ち込まない。
- APIに定められた型・呼出し規約を使う。`int`や`long`の幅を推測せず、オーバーフロー、符号変換、数値精度、フィルタ遅延を対象仕様から確認する。
- 文字コード、ファイル名、ヘッダ構成、エクスポートの要否は既存規約に合わせる。規約が未提示なら未決として明示する。アラーム用自動プロファイルだけはASCIIのC/Hを使う。
- 不要な公開API、DllMain、推測したSDKのスタブを加えない。DLL内部の関数と、DLLの公開インターフェイスを混同しない。

## RTOSと状態

ファイル、時刻、CPUロック、レジスタI/O等は、提供APIの契約で許される文脈から呼ぶ。Win32やCランタイムによる直接操作へ置き換えない。API名だけでなく、実行文脈、ブロックの有無、戻り値、失敗時処理、ロックの解除条件を確認する。

状態・出力領域の寿命、非重複、再入可能性と他タスクからのアクセスを確認する。`volatile`だけで同期が成立すると扱わない。ロック・待機・動的確保・再帰・文字列整形は、仕様と時間予算で認められた範囲に限る。ループが必要な処理では上限を説明する。アラーム判定プロファイルは外部API・ループ・共有静的状態を禁止しているが、この固有条件を他の制御ルーチンの仕様へ勝手に追加しない。

## 対応表と検証

`traceability.md` は仕様ID/手順 → 実装箇所 → 確認方法を示す。コードの行番号だけに依存せず関数名とコードハッシュも記録する。未実装・呼出し側責務・未決事項を欠落なく引き継ぐ。

ビルドと動的試験は別々の結果として記録する。C90モード・警告・最適化条件、試験対象のコード、ツール版・入力版が追跡できるようにする。処理量が有界なことから実機のWCET保証を導かない。生成記録の自己申告は署名や第三者認証ではない。
