# 単体テスト仕様書作成のチーム規約

固定されたAlarmQualification_Updateの単体テスト仕様書を作るときは、プロジェクトの `routine-unit-test-spec` スキルと固定OfficeCLIアダプターを使う。案件は `.bob` の外へ置く。既存コードPoCを `new-job --code-job` で取り込み、入力と配布版のロックを維持する。

案件の `source/unit-test-spec.json` が正本である。期待値はプログラム仕様から導き、ソースで追加観点を確認する。旧試験・旧合格ログは設計固定後の比較用とし、新規ケースへ合格を転記しない。全ケース・族・静的確認は未実施として出力する。

入力・固定資材・実行実体の不一致や検査失敗は理由を報告して停止する。ロックや固定資材の書換え、別版の導入、別の文書生成器への切替で回避しない。Word内部の変更はOfficeCLIへ統一し、内容の改訂はJSONから新しいrun IDへ再展開する。

内容・書式照合と構造検査の結果を確認し、全ページ表示確認は別に記録する。文書生成を試験合格・要求承認・RTOS性能確認と扱わない。Bobで実行していない作業はBob実施済みと記録しない。
