# 正本を作成・改訂する際の参照

## 対応範囲

この配布版は、既存試作の `AlarmQualification_Update` 1ルーチンを対象とする。スキーマはサンプルの形を固定したもの、組込み検証器は使用キーワードだけを扱う限定実装である。任意ルーチンの汎用標準ではない。

要求例全体のPLC読取り、ランプ出力、画面公開、ログ予約は呼出し側の担当である。今回のルーチンは連続ON判定と新規成立通知だけを扱う。1周期1回、最初の有効ONを1回目と数える、10回目に通知する、OFF／無効入力で0へ戻す、等は未承認の試作用前提である。

## 編集対象

`source/spec.json` が正本である。文書の版・説明・仮定・未決事項等を改訂できるが、意味上の整合性は人による確認が必要である。`describe` が示す固定スキーマと記述例を参照し、必須項目を消さず、未定義項目を追加しない。

| 項目 | 記述すること |
|---|---|
| `overview` | 原要求、原要求の所在、対象範囲 |
| `trial_assumptions` | 試すために置いた前提と識別ID |
| `interface` | C90の型・引数・戻り値・領域所有条件 |
| `behavior` | 状態・初期値・手順・条件表・事後条件 |
| `constraints` | 周期、資源、RTOS基盤API、並行実行の制約 |
| `verification_examples` | 仕様を確認する入力と期待結果。実行済の試験結果ではない |
| `traceability` | 要求・担当仕様・確認例の対応 |
| `open_issues` | 未決事項と判断担当 |

10周期判定以外の要件、実APIへの接続、時間予算の確定は、この配布版を自動的に書換える理由にはならない。未対応箇所と必要な改訂を記録する。版改訂・依存更新・テンプレート変更は保守者の作業とする。

## 確認結果

`validate` は構造と限定した規則だけを検査する。`render` は固定テンプレートの繰返し行をOfficeCLIで複製し、値を差し込んでからOfficeCLIのOOXML検査を行う。入力控え、編集命令と実行結果、構造検査、内容・書式・フィールドの照合、manifestを新しい展開IDへ出力する。JSON全体の意味、要求の網羅、C90コンパイル、RTOS性能、文書の改ページは確認しない。

正本の変更差分とWordの見え方を確認し、残る仮定・未決事項と確認範囲を利用者へ示す。`package-lock.json` を変更して不一致を回避しない。旧案件には一致する旧配布版を使い、移行が必要なら明示した保守変更として扱う。

この版は、承認済みOfficeCLI 1.0.144の実体ハッシュを固定する。通常処理は標準ライブラリだけで実行でき、python-docxやlxmlは使わない。OfficeCLIが付加する監査時刻等でDOCXのバイト列が変化し得るため、同一内容の比較にはmanifestの意味・書式モデルのハッシュを使う。出力ファイル自体のハッシュも別に記録する。
