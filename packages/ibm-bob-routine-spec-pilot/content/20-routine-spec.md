# ルーチン仕様書作成のチーム規約

ルーチン単位のプログラム仕様書をJSON正本からWordへ展開する作業では、プロジェクトの `routine-spec-doc` スキルを使い、配布済の固定CLI・スキーマ・テンプレートを再利用する。案件データは `.bob` の外へ置く。

この初回版は10周期連続ON判定ルーチンの `draft_trial` 限定。対応外の要求は不足項目と必要な改訂として整理する。通常作業で変換処理やテンプレートを再生成せず、検証を通すために契約を緩めない。資材不一致は保守担当へ戻す。

Word生成後は、利用可能なBob標準 `office_read` で内容を読み、validateモードでOOXML構造を確認して結果を保存する。構造検査が利用できなければ未確認と報告する。表示・意味・RTOS性能の合格とは区別する。生成Wordの仕様変更はJSON正本へ戻して再展開する。

RTOS API名、DLL ABI、C90規約、呼出し文脈、時間予算は案件の正式資料に従う。資料がなければ前提・未決事項として残し、推測で確定しない。
